# Branded error recovery

OpenZcash keeps three distinct states: an unexpected page error, a missing page, and an unavailable service. None exposes exception messages, database details or stack traces to visitors. Do not attribute a generic exception to a data source without evidence.

## Application coverage

- `src/app/error.tsx` handles errors under the root layout. **Try again** calls Next 16.3's `retry()` to fetch the segment again and render it, rather than just resetting the existing error.
- `src/app/global-error.tsx` handles a failed root layout. It includes its own document, inline CSS and the embedded official mark. It has no dependency on the shell, database, router, image server or font loader.
- `src/app/not-found.tsx` handles unmatched pages and `notFound()` results. It offers a full-document home link. Next owns the HTTP status, including its normal streaming semantics.
- Existing inline source errors and API response contracts remain in place. A React error boundary does not catch every event-handler or asynchronous error; those must still be handled at the operation that can fail.

The embedded image is byte-identical to `public/logos/marks/openzcash.png`. In the app, the fallback uses the surrounding theme; the standalone page follows the operating system's color preference without requiring JavaScript. Both respect reduced motion and keyboard focus, with 48px actions on mobile.

## Whole-origin outages

`public/service-unavailable.html` is a self-contained export of the same UI, generated by `npm run errors:build`. `npm run errors:check` verifies that it matches the component and official mark. The reload link works without JavaScript and stays on the current URL when the HTML is served as an error response.

**Serving this file from Next alone does not replace Railway's 502 page when Next or Railway is unreachable.** The optional `ops/error-fallback/` package must run on an independent edge service in front of the origin to cover that case. It is prepared for review, not activated. No DNS, domain, Railway service or production configuration is changed by this implementation.

The edge response must preserve a failing status (503), `Cache-Control: no-store`, `Retry-After`, and `noindex`. API, React Server Component, asset and mutation requests must retain their existing contracts. Never turn a failure into a successful-looking data response.

## Local review

Run `DISABLE_AUTO_REFRESH=true npm run dev -- --hostname 127.0.0.1 --port 4234`.

- `/error-preview`: page/404 previews and a real client-exception/recovery fixture.
- `/error-preview?simulate=page`: trigger the error, then select **Try again** to recover.
- `/a-page-that-does-not-exist`: real missing-route behavior.
- `/service-unavailable.html`: the independent HTML design, usable without JS or external assets.

`/error-preview` is available only in development and returns not-found in production. Do not add an externally reachable production crash switch. Test origin failures with the isolated edge harness, never by stopping the live site.
