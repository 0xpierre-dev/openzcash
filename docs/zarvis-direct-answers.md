# Zarvis direct answers

## What is free of model tokens

Auto and Quick use reviewed text or validated public-data formatting for the complete supported question. No provider client is created in this path, and there are zero model input/output tokens and zero hosted AI searches. Public database reads, quote providers and official ZIP refresh requests still run when needed; hosting costs and normal request quotas remain.

| Subject | Example | Source/behavior |
| --- | --- | --- |
| Zcash basics | What is Zcash? / ¿Qué es Zcash? | Reviewed EN/PT/ES explanation and source |
| Privacy and keys | What can a Sapling incoming viewing key reveal? | Incoming/full/outgoing distinctions; no spending authority |
| Supply and halvings | What is 5% of 21 million ZEC? | Fixed maximum versus changing circulating supply |
| Site navigation/methodology | Where is the treasury calculator? | Existing public OpenZcash pages |
| Mining definitions and source comparison | What is solrate? / Why do ZcashInfo and ZecStats show different hashrates? | Reviewed methodology, units, averaging windows and attribution limits |
| Current network solrate | Qual é o hashrate atual da rede Zcash? | Validated ZcashInfo API snapshot, 20 blocks, heights and UTC timestamps; 60-second cache |
| USD price | Qual é o preço do ZEC? | Shared quote with its time and stale state |
| Community holdings | What are the latest ZCG and Lockbox balances, and how old are the data? | Dated ZCG report and import with their ages, block-based Lockbox estimate with its anchor age, separate quote with its age |
| Grant payments | How much has ZCG paid in grants? | Full selected ledger aggregate, historical budget values |
| Scoped grant payments | How much did coinholders pay in grants to Zingo in 2025? | Program/year and literal project/recipient/milestone fragment |
| Numbered ZIPs | What is ZIP 317? | Exact document, revision-specific status, Created and official abstract excerpt |
| Latest ZIP | What is the latest ZIP? | Fresh catalog ordered by declared Created date, not publication or highest number |
| Latest Arborist call | What was the latest Arborist call? / Qual foi a última reunião arborist? | Newest call in the cached notes/recordings archive: number, meeting date, moderator, agenda, notes and recording links; a recording without notes is labelled provisional; an unreadable archive links to /arborist instead of inventing a call |

Reviewed fact/navigation topics have English, Portuguese and Spanish text, and every intent above has Spanish phrasings (the corpus in `src/lib/zarvis/direct-paraphrase.test.ts` and the list in [zarvis.md](./zarvis.md) are the reference). Numbered ZIP abstracts are quoted in their original language, explicitly labeled as English in Portuguese and Spanish answers. They are not model translations or technical analyses.

The language of a direct answer is the language of the question, decided by `src/lib/zarvis/language.ts` (weighted word majority with function words above domain nouns; everyday Portuguese that is also Spanish — se, vale, usa, pago, use, usar, sobre, por, dólares — is in both lists so "Como se usa uma viewing key?" and "Use dólares" stay Portuguese; a Portuguese/Spanish tie goes to Portuguese unless the raw text carries ¿, ¡ or ñ; previous-turn fallback; explicit stored preference first), not by the pattern that matched: "Quais são os saldos do ZCG?", "Uma IVK identifica o remetente?", "Onde encontro carteiras Zcash?", "Saldo do Lockbox", "Saldo ZCG", "Último ZIP" and "Como funciona a viewing key?" answer in Portuguese, "¿Qué significa ZCG?", "Háblame de Zcash", "Total pagado por ZCG" and "¿Último ZIP?" answer in Spanish, while "and the Lockbox?" after a Portuguese question answers in English. A French question, or one in any other language without templates, matches no direct pattern and goes to the model. Direct answers arrive with `provenance.route = "local"` and `model = null`, and the chat labels them "Direct from OpenZcash data · no AI" / "Direto dos dados OpenZcash · sem IA" / "Directo de los datos de OpenZcash · sin IA".

## Paraphrases

Matching is exact per pattern, but the question is normalised first. The exact form is tried, then a relaxed form with conversational filler removed (`relaxed()` in `src/lib/zarvis/direct-intent.ts`): a leading "Hey Zarvis / Oye Zarvis", "please / por favor", "can you / could you / puedes / podrías / me puedes", "do you know / sabes", "I want to know / quero saber / quiero saber / me gustaría saber", "tell me / me diga / me explica / dime / explícame / cuéntame", "just"; and, anywhere, "right now", "currently", "at the moment", "today", "now", "hoje", "agora", "atualmente", "neste momento", "hoy", "ahora", "actualmente", "en este momento", "ahora mismo", "for me / pra mim / para mí", "please / por favor"; "ZCG's" becomes "ZCG"; trailing punctuation was already dropped. The exact form comes first so "and now?" after a price question keeps its meaning. Each intent accepts synonyms: price — worth / trading at / going for / cost / price of / value of / quanto vale / valor / cotação / cuánto vale / cuesta / precio / cotización ("la cotización del ZEC"); grant payments — paid / paid out / spent / disbursed / distributed, "total grant payments by ZCG", "ZCG grant spending", gastou / desembolsou / total pago pelo, cuánto pagó / ha pagado / total pagado por; balances — how much is in / holds / has in its treasury / balance of / holdings / reserves / how big is, quanto tem no / possui / tamanho da tesouraria / na tesouraria do, cuánto tiene / hay / posee / guarda ("… en ZEC / en efectivo / en tesorería", "en la tesorería de ZCG"), saldo(s) del, tesorería del; definitions — what does X mean / stand for, define, tell me about, explain what X is, o que significa, me fale sobre, qué significa / quiere decir, háblame de(l), cuéntame sobre, plus an article before the term. `src/lib/zarvis/direct-paraphrase.test.ts` keeps a corpus of about eighty EN/PT phrasings and a hundred Spanish ones with the expected intent or "model", and checks that every Spanish direct phrasing answers in Spanish; every qualification (yesterday, in BRL, if it rises 20x, excluding…, compared to…, trend, runway) still goes to the model.

## Context

"Latest Arborist call" is the only Arborist template; "what was discussed in the latest call about Zaino" or "call #131" keeps model synthesis with the `arborist` topic pre-filtered by the question.

Supported follow-ups retain the known subject: “e em 2025?” keeps the ledger program and project; “e o Lockbox?” switches the fund; “and how old are the data?” keeps the fund and restates its dated stamps; “when was it created?” keeps the exact ZIP number. Greetings, thanks and supported EN/PT/ES, USD and brief-response preferences ("Responde en español", "¡Usa dólares!", "Sé breve") do not erase that subject. Explicit stored preferences are respected.

Direct routing is suppressed only after an earlier user turn that reads as an instruction or preference (`looksLikeInstruction`): an imperative opening (answer, use, write, keep, be, show, include, ignore, calculate, responda, use, escreva, seja, responde, contesta, escribe, muestra, calcula, …; the Spanish "usa" and "resume" count only with a Spanish object — "usa euros", "resume esto" — because "USA regulation of Zcash?" and "Resume of ZCG history?" are English questions), always / only / never / from now on / sempre / somente / nunca / a partir de agora / siempre / solamente / de ahora en adelante, or format, language, currency, length, tone or persona words (JSON, table, English, French, BRL, brief, detailed, act as, …). Such a turn might set constraints the templates cannot honour, so the whole conversation stays on model synthesis. An earlier open question that matched nothing ("Who is Zooko?", "Is ZEC a good investment?") no longer disables the free route: the next supported question ("What is the ZEC price?") answers directly, and only the follow-up subject is reset, so "e o Lockbox?" after an unrelated question goes to the model instead of guessing. A bare “yes/sim” is not turned into a repeated factual answer. Deep analysis always uses the selected model. Except for a fully matched reviewed methodology FAQ, comparisons, predictions, technical reasoning, unsupported currencies/languages, detailed-response preferences and additional qualifications retain model synthesis even when the underlying facts exist internally.

## Data limits

- Missing amounts are never silently zero. Unsupported or unavailable price/treasury/ledger data produces a local unavailable answer, preserving what can be verified.
- ZCG cash excludes past grant spending. Lockbox values are accrual estimates, not fresh wallet balances. Later outflows may require reconciliation. Combined valuation rounds each pool like the existing calculator/footer and does not imply a single spendable pool.
- Grant totals cover the whole selected ledger, not search excerpts. Negative returns, missing fields, historical USD budget values, recorded ZEC disbursements, program separation and payment-date filtering keep their existing meanings. Project matches are literal text fragments, not confirmed unique identities.
- Stale or missing requested ZIPs fall back to the existing evidence/research path. Created is not first publication, and document status is not network activation.
- This is bounded deterministic coverage, not a promise to answer every paraphrase or every internal-data question for free. No actual-traffic savings percentage is claimed.

## Verification

The direct orchestration suite runs the real local planner with public-reader fixtures and a provider mock that throws on any unexpected billed request. It verifies zero client creation, zero model/search calls and zero tokens, completion and citations, supported context, malformed/missing data, intentional model fallback for unsupported or Deep requests, Portuguese output for twelve Portuguese phrasings (treasury, price, ZIP, ledger and FAQ) with local provenance, Spanish output with `provenance.language = "es"` for twenty-odd Spanish phrasings (including the tied-looking "¿Qué significa ZCG?" and "Total pagado por ZCG"), cross-language follow-ups, stored Spanish preferences written with ¡…!, a Spanish qualified question reaching the model with a Spanish badge, and a French question reaching the model with an English badge.

Run `npx vitest run src/lib/zarvis/direct-intent.test.ts src/lib/zarvis/direct-data.test.ts src/lib/zarvis/direct-orchestration.test.ts src/lib/zarvis/local.test.ts src/lib/zarvis/openai.test.ts src/lib/zarvis/language.test.ts src/lib/zarvis/provenance.test.ts`.

Live verification uses synthetic questions against the loopback preview with counts-only development diagnostics. Diagnostics contain no questions, answers, IPs or credentials and remain disabled in production. A fast reply alone is not proof of zero model usage.

### Local live run — September 28, 2026 UTC

Twenty-three synthetic requests, including multi-turn sequences, returned completed answers with `route=local`, `modelCalls=0`, `inputTokens=0`, `outputTokens=0` and `webSearchCalls=0`. Reads used the actual preview's public data and ZIP catalog, not fixtures. HTTP durations were 6–955 ms on the local machine; this is not a production latency guarantee. The browser also rendered an incoming-viewing-key answer and its spending-authority follow-up with sources.

The final automated run passed 895 Vitest tests plus 3 knowledge-build tests; 9 optional database tests were skipped. An earlier rerun hit three 5-second timeouts while the machine was under concurrent load; the full suite then passed with `--maxWorkers=2`, without changing test assertions or timeouts. Changed-file ESLint also passed.
